# UPnPtweaker

一个自用的小工具:通过 **UPnP / IGD** 协议操作家里路由器的端口转发(NAT 端口映射),
用图形界面点点点就能加规则、删规则、看外网 IP,不用再登路由器后台翻菜单。

**纯 Python 标准库实现,不需要装任何第三方包。**

---

## 运行

需要 Python 3.10 以上(Windows 官方安装包自带 tkinter,无需额外安装;
Linux/macOS 上要单独装,见下面的「兼容性」)。

**Windows:双击 `start.bat`**(无控制台窗口)

**Linux / macOS:**

```bash
./start.sh
```

**或者直接命令行:**

```bash
python main.py          # Windows
python3 main.py         # Linux / macOS
```

打开后:

1. 点 **「搜索设备」** —— 自动在局域网里找支持 UPnP 的路由器
2. 顶部下拉框会列出找到的 WAN 连接服务(多拨/多 WAN 时会有多个,选正在用的那个)
3. 选好后自动刷新:**外网 IP**、**连接状态**、**现有端口映射列表**

## 界面用法

### 看现有规则

中间表格列出路由器上所有端口映射:描述、协议、外部端口、内部 IP、内部端口、租期、状态。

- **双击某一行** = 把它的参数填进下面的表单(改端口重加最方便)
- **「用选中项填充表单」** 同上
- **「检查该端口」** = 查某个外部端口当前指向哪里

### 添加 / 覆盖规则

在下方表单填:

| 字段 | 说明 |
|---|---|
| 常用 | 预设:远程桌面 3389、HTTP 80、Minecraft 25565 等,选了一键填好 |
| 协议 | TCP 或 UDP(多数场景选 TCP;游戏、BT 常要 UDP) |
| 租期 | 规则有效期,`永久 (0)` / 1 小时 / 1 天 / 7 天 / 30 天,也可直接填秒数 |
| 描述 | 随便写,方便以后认出来 |
| 外部端口 | 公网访问用的端口 |
| 内部 IP | 要转发到的局域网设备地址。**默认已填好本机 IP** |
| 内部端口 | 目标设备上真正监听的端口(一般和外部端口相同) |
| 远程主机 | 留空 = 允许任何来源(推荐);填了则只允许该 IP 访问 |

点 **「添加 / 覆盖映射」**。

- 如果该外部端口已被占用,会弹窗告诉你旧的指向哪里,确认后才覆盖
- 内部端口留空 = 与外部端口相同

### 删除规则

选中表格里的一行 → **「删除选中」** → 确认。

> 表格里那些 `MiniTP SDK`、`pgyvisitor` 是别的软件(向日葵、花生壳之类)自己加的规则,
> 删之前先确认不是你在用的远程工具。

## 命令行模式

排查问题时比图形界面好用:

```bash
python main.py scan                      # 搜索路由器,列出型号和控制地址
python main.py list                      # 列出所有端口映射
python main.py ip                        # 只看外网 IP
python main.py add 8080 192.168.1.5      # 外部 8080 → 192.168.1.5:8080
python main.py add 8080 192.168.1.5 80   # 外部 8080 → 192.168.1.5:80
python main.py add 6881 192.168.1.5 -p udp -l 604800
python main.py del 8080                  # 删除 8080/TCP
```

`add` 的参数顺序是 `外部端口 内部IP [内部端口]`,`-p` 指定协议,`-l` 指定租期秒数。

## 验证是否真的生效

**这一步很重要** —— 路由器上显示"添加成功"不代表公网真能访问。

1. 先在目标机器上起一个服务监听该端口,比如 `python -m http.server 8080`
2. 用手机流量(不是家里 Wi-Fi!)访问 `http://<外网IP>:8080`

如果访问不通,最常见的原因是 **运营商大内网(CGNAT)**:你的"外网 IP"其实是运营商内网地址,
外部根本无法主动连入。判断方法:把界面显示的**外网 IP** 和[访问这个页面](https://api.ipify.org)
看到的 IP 对比 —— 两者不一致就说明你在 CGNAT 后面,需要打运营商客服申请公网 IP。

## 已知限制

- **租期可能被路由器改写**。华为 AX3 Pro 实测会把"永久"自动压成 7 天。这是路由器行为,不是本工具的 bug。
- **每个路由器对参数的支持程度不同**。有些固件不支持指定远程主机、不支持非永久租期,会返回 725/728 之类的错误 —— 错误提示里已经翻译成中文了。
- **只实现了 IPv4**。IPv6 通常不需要端口映射,所以没做。
- **和别的软件会抢端口**。迅雷、BT 客户端、远程控制软件都会自己加 UPnP 规则,冲突时提示"端口已被占用"是正常的。

## 兼容性

### 操作系统

| 系统 | 图形界面 | 命令行 | 启动方式 |
|---|---|---|---|
| Windows | ✅ | ✅ | 双击 `start.bat` |
| Linux | ✅ 需装 tkinter | ✅ | `./start.sh` 或 `python3 main.py` |
| macOS | ✅ 需装 tkinter | ✅ | `./start.sh` 或 `python3 main.py` |

Linux/macOS 上 tkinter 常常要单独装:

```bash
sudo apt install python3-tk        # Debian / Ubuntu
sudo dnf install python3-tkinter   # Fedora
brew install python-tk             # macOS (Homebrew)
```

**命令行模式不需要 tkinter** —— GUI 是延迟导入的,无图形界面的服务器上可以直接用
`python3 main.py list`,不会因为缺 tkinter 而报错。

### Python 版本

语法上 **3.7+** 都能解析,只用到 `dataclasses` 这类很老的特性。实际测试在 3.14 上。
推荐 3.10 以上。

### macOS 特别注意

macOS 15(Sequoia)及以后,首次运行时系统会弹窗询问**「允许访问本地网络」**,
必须允许,否则 SSDP 组播发不出去,搜索会一无所获。

### ⚠️ 不能用的环境:WSL / Docker / 虚拟机桥接网络

这几个环境**收不到 SSDP 组播响应**:

- **WSL2** 走的是 NAT 虚拟网卡,组播到不了局域网(需要折腾 mirrored networking 模式)
- **Docker** 默认 bridge 网络隔离了组播
- **虚拟机** 如果用的是 NAT 网络而非桥接,同理

要在这些环境里用,得让网络模式变成"桥接/镜像",让容器或虚拟机拿到局域网的地址。

### 路由器

按标准 UPnP IGD 协议实现,同时搜索 IGD **v1 和 v2**、以及 `WANIPConnection`
和 `WANPPPConnection` 两种服务,覆盖绝大多数家用路由器。

不工作的情况:

- 路由器**关了 UPnP** —— 最常见,去管理页打开
- **运营商光猫在拨号**,你的路由器只是二级路由 —— 映射得加在光猫上
- **运营商大内网(CGNAT)** —— 映射能加上,但公网访问不了,需要申请公网 IP
- 少数企业级/运营商定制固件**禁用了 IGD 服务**

### 已知不支持

- **IPv6** —— IPv6 通常不需要端口映射,没做
- **HTTPS 的设备描述地址** —— 极罕见;`device.py` 只走 HTTP
- **NAT-PMP / PCP** —— 只实现了 UPnP IGD

## 代码结构

```
main.py              入口:GUI / 命令行分发
start.bat            Windows 双击启动(无控制台窗口)
start.sh             Linux / macOS 启动脚本
upnptweaker/
  ssdp.py            SSDP 发现 —— 组播 M-SEARCH 找路由器
  device.py          下载解析设备描述 XML,找出 WAN 连接服务
  soap.py            SOAP 控制调用,UPnP 错误码 → 中文
  igd.py             IGD 高层 API:增删查端口映射
  gateway.py         把上面几层串成"给我一个能用的网关"
  gui.py             tkinter 界面
```

三层协议栈(SSDP → 设备描述 → SOAP)都是手写的,没有依赖 `miniupnpc` 之类的库,
方便自己改着玩。

## 安全提醒

### UPnP 不需要路由器密码

这一点必须先讲清楚:**UPnP 协议本身没有任何认证**。路由器收到局域网里的
UPnP 请求就直接执行,**不会验证密码**。

想亲眼确认的话,任意命令后面加 `--debug`,会打印完整的原始报文:

```bash
python main.py ip --debug
```

你会看到请求里只有 `Content-Type`、`SOAPAction`、`Content-Length`、`Connection`、
`User-Agent` 五个头 —— **没有 `Authorization`,没有 Cookie,没有 token**,
HTTP 正文里也只有一个动作名。路由器回了 `HTTP 200` 和你的外网 IP。

这是因为 UPnP 的安全模型是「**在局域网内 = 可信**」,它假设能往路由器发组播包的
设备就是主人的设备。路由器的管理页面密码保护的是 Web 后台(`192.168.3.1`),
**UPnP 是完全独立的另一条通道**(华为这台在 37215 端口),根本不看那个密码。

含义:

- 同一局域网内**任何设备**都能给路由器开端口,不只是这台电脑 ——
  也包括手机、智能电视、IoT 设备、访客设备
- 路由器改密码**不影响** UPnP 通道;唯一的总开关是路由器里的 UPnP 开关
- 映射一旦建立,公网任何人都能连那个端口,和「谁建的」无关

### 端口映射本身的建议

UPnP 端口映射等于**在防火墙上开洞**,让公网能直接连到你内网某台机器。建议:

- 只映射确实需要的端口,**用完就删**
- 尽量用非默认端口(比如远程桌面别用 3389,换个高位端口)
- 内网 IP 要填对 —— 填错设备等于把别人的机器暴露出去
- 公共服务尽量走 VPN / 内网穿透,而不是直接暴露端口

### 分享给别人时

把整个文件夹拷给对方就能用(纯标准库,无需 `pip install`),对方需要
Python 3.10+ 并且和自己的路由器在同一局域网。但请注意:

- **先说清楚它做什么** —— 它能在对方的路由器上开公网端口。不理解用途的人
  开完就忘,会留下永久敞开的洞
- **不要拿到公共/共享网络用**(宿舍、公司、咖啡馆)。那些环境里 UPnP
  通常已被禁用,而且本身就是安全隐患
- 配置只存在 `~/.upnp_portmapper.json`(用户主目录,不在这个文件夹里),
  拷文件夹不会带上你的内网布局

### 这个工具没有创造新的攻击面

它用的就是标准 UPnP 协议,任何 UPnP 客户端都能做同样的事 —— 你路由器上那
4 条 `MiniTP SDK` / `pgyvisitor` 映射,就是迅雷和蒲公英自己加的,**它们也从没
问你要过密码**。

反过来说,这个工具的价值在于**可见性**:以前这些软件偷偷加了什么你根本不知道,
得登路由器后台翻才能看见。

配置文件保存在 `~/.upnp_portmapper.json`,只记录了表单上次填的值,没有敏感信息。
